# 真实终端能力与自测

## 实现

- portable-pty 为每个标签创建独立 PTY，启动当前用户的登录交互 Shell（优先 `$SHELL`，其次系统账户的 `pw_shell`，最后 `/bin/zsh`），加载用户的登录环境。
- xterm.js 提供 ANSI/VT 显示、中文输入输出、交互程序、键盘导航、Ctrl+C、复制粘贴和输出搜索。保存 5000 行滚动历史；输出保留原始字节，避免 UTF-8 多字节字符在 IPC 分片处损坏。
- 每个会话在前端拥有独立 runtime；切页/隐藏仅移动容器，不结束后端。ResizeObserver 自动调整 PTY 行列。退出状态由独立 reaper 监控，后台任务持有 slave FD、输出背压均不会阻止 Shell 收尸。
- 快捷指令先在指定目录创建真实终端，再写入原始命令，名称和标签仍由现有指令管理器维护。
- Channel 流采用 256 KiB 在途窗口（最多额外一个 8192 字节分块），xterm 完成解析后确认字节数；后台会阻塞输出读取，避免 WebView 被无限输出占满。
- 关闭标签显式确认；后端只清理仍运行的当前 PTY 的 POSIX session 内进程，包括不同进程组的前台、后台任务。检查子进程存活和发送信号期间持有同一把子进程锁，已退出会话不会按旧 PID 发信号。关闭后显式释放 master/writer，reader 通过 100ms poll 观察关闭并释放克隆 FD，避免 macOS TTY 退出阶段等待资源的循环。应用退出关闭自己的会话。用户显式 disown 并退出 Shell 的任务视为已脱离会话，不按旧 PID 回杀。
- 原生剪贴板通过统一 `writeClipboard/readClipboard` 服务，支持 Cmd+C 复制选中内容、Cmd+V 粘贴；Ctrl+C 保持终端中断语义。清屏与搜索按钮使用已有组件；Ctrl+L 保留 Shell 清屏语义，Cmd+K 留给全局快速操作。
- 普通浏览器不启动模拟 Shell，会明确提示从桌面 App 打开真实终端。

- 输入由专属有界 worker 写入：累计最多 256 KiB、最多 32 个待处理请求，超限立即返回明确错误。PTY 为非阻塞 IO，IPC 不执行 write_all；关闭不等待被堵写锁，worker 检查关闭标志后释放资源。输入饱和时 Ctrl+C 优先取消未写完的粘贴、清理 TTY 队列并中断本 PTY 前台进程组，避免中断指令排在大粘贴后面。

## 自动验证

2026-10-15 执行：

```sh
cargo test --manifest-path src-tauri/Cargo.toml terminal::tests --lib -- --nocapture
```

终端模块：8 项。集成默认并行测试结果见下方最新回归记录。

夹具先等待真实登录 Shell 的 ready 标记，再检查交互；考虑用户 zshrc/Conda 初始化在并行负载下的耗时，启动与输出使用整体 30 秒 deadline、每秒检查。关闭自身任务仍要求 1 秒内返回，并验证进程最终消失。

| 用例 | 实际验证内容 |
| --- | --- |
| real_interaction_resize_interrupt_and_exit | 创建真实 PTY、交互命令返回输出、中文输出、`stty size` 验证 31×101、运行 sleep 后 Ctrl+C 中断并继续执行、exit 7 返回准确退出码 |
| concurrent_sessions_and_close_own_group | 两个独立真实会话各自输出；关闭一个 shell 后确认 PID 已退出，另一个仍可执行命令 |
| closing_cleans_foreground_and_background_jobs | 自建前台 sleep 和后台 sleep，记录真实 PID，确认关闭不阻塞且 shell/两个 job 均已消失 |
| output_is_backpressured_without_renderer_ack | 运行真实 yes，不发送渲染确认；在途字节达到窗口后停止增长，关闭可正常清理 |
| shell_exit_is_reaped_while_background_job_holds_pty | 后台 sleep 持有 PTY 时，Shell exit 9 仍及时上报且已收尸；fixture 单独清理自己 disown 的 sleep |
| closing_exited_session_never_signals_reused_pid | 用另一条自建 sleep 模拟旧 PID 被复用，关闭已退出 session 不会结束该 sleep |
| blocked_large_input_is_bounded_and_close_remains_responsive | 前台 sleep 配合非 canonical/noecho 模式停止读取，256 KiB 粘贴受限，超限立即错误；饱和队列中 Ctrl+C 可取消粘贴并继续执行命令；再次堵塞后关闭小于 1 秒，Shell 收尸 |
| invalid_directory_and_dimensions | 拒绝不存在/相对目录，约束终端行列范围 |

自动测试只创建并结束自身的 Shell、sleep、yes；不操作用户已有终端或服务。测试均由 Drop/close_all 清理。

## 原生桌面端验收

已在打包后的 WKWebView 中验证：真实本地命令与工作目录、交互 `top`、快捷指令新建会话、复制命令到系统剪贴板、输出搜索、四页切换后保留输出、双击重命名、全局 ⌘K、深浅配色、App 退出后所属 Shell 清理。含 ASCII 引号的命令保存后逐字符核对持久化文件，并成功执行。截图及具体结果见 [真实功能验收](./真实功能验收.md)。

自动测试不替代所有输入法、各显示器缩放比例和不同 macOS 版本的兼容性检查；这些兼容组合不作为本机已验证能力的扩大声明。SSH 使用同一个 renderer，独立认证、远程通道及文件操作的证据见 SSH 自测文档。

8 项终端测试全部参与每轮；4 个 ignored 是需要专用 SSH/钥匙串夹具的显式集成测试，未被本记录计为通过。没有使用单线程参数，没有只选取终端子集代替全量结果。此次回归保留 PID 消失、close <1 秒等原始严格断言。

之前发现的关闭失败实际捕获为 macOS `(zsh)` / `?Es` 退出阶段进程：仅发送信号、独立 reaper 都不足以解决，必须同时显式释放 PTY master/writer 并让 reader 观察关闭标志释放克隆 FD。测试过程中还修复了“PID 文件存在但内容未写完”的 fixture 竞态。
