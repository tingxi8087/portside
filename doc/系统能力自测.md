# macOS 端口与进程能力自测

日期：2026-10-15。环境：macOS 26.6.2，当前登录用户权限。本文只记录系统模块的证据，终端、SSH、文件与外观由对应模块单独验收。

## 实现与口径

- `/bin/ps` 读取真实 PID、父进程、UID、用户名、RSS、启动时间、完整启动参数；`proc_pidpath` 读取程序路径。
- `proc_pid_rusage(RUSAGE_INFO_V2)` 获取 CPU 时间、精确启动标识、磁盘累计字节数。CPU 用相邻采样时间差计算并除以逻辑核心数，显示进程占整机的比例；所有逻辑核心满载合计为 100%。首次采样显示 `—`，不拿 0 代替尚未采集的数据。
- 内存使用 `proc_pid_rusage` 的 `ri_phys_footprint`，以十进制 MB / GB 显示，与活动监视器口径一致；读取失败显示 `—`，不回退到 RSS。磁盘为进程的读写累计字节差，以 KiB/s 显示，受 macOS 内核记账及缓存行为影响，不能等同于文件写入量。
- `/usr/bin/nettop -P -L 1 -n -x -J bytes_in,bytes_out` 读取每进程 TCP / UDP 计数，再差分为上传、下载 KiB/s。新进程、没有可观察套接字、计数回退、权限受限时显示 `—`。不把未被 nettop 观察到的进程当成零流量。
- `/usr/sbin/lsof` 读取 TCP LISTEN 与 UDP 绑定端口，支持 IPv4 / IPv6、按协议 / 地址 / PID 去重；无具体数字端口的 `*:*` 跳过。UDP 已连接套接字取本地端点。
- 两页共享 single-flight 采样和后端缓存；只在端口 / 进程路由可见、窗口文档可见且没有暂停时每 2 秒读取。暂停保留当前数据。隐藏页面不会单独启动采集。
- 所有工具使用绝对路径与独立参数，不经过 shell。单个工具采集最长 8 秒，失败显示错误并保留上次成功数据；采集在 blocking worker 中运行。
- 选中对象使用 PID + 启动时间 + 精确启动计数 + 程序路径标识。终止前再次读取身份，防止对已复用的 PID 操作。普通结束发送 SIGTERM；1.2 秒后仍存活才提示用户选择 SIGKILL。不会自动升级权限；权限失败如实显示。
- 拒绝 PID 0 / 1、Portside 自身、超出有符号 PID 范围的目标。系统 / 其他用户进程额外确认；结束对象始终是整个进程，所有关联端口都可能关闭。

## 能力限制与仍需整体验证

- 当前权限能观察到的进程和端口不是全系统保证；macOS SIP / 其他用户 / 权限限制会使路径、命令、CPU / 磁盘或网络字段不可用。不会显示合成的 0，也不会声称已授权读取所有数据。
- nettop 统计当前可观察 TCP / UDP 套接字，不包含所有类型 IPC；关闭套接字可能导致累计值回退，这次样本被标为不可用。
- `ps` 的启动命令由操作系统提供，可能受到进程自修改参数影响。执行身份以启动标识与路径再校验，仍不能为 macOS 无 pidfd 的信号接口提供原子核验 + 发送保证。
- 尚未为系统应用加入提权助手；权限不足会失败并提示。进程一键结束使用 SIGTERM，不是应用菜单中的“退出”，运行中任务可能中断。
- 显示“程序路径不可用”时仍可查看其余已采集字段；列表按名称、PID、CPU、内存、磁盘、网络排序，缺失值在正序和倒序均排在末尾。
- 需要主智能体在最终桌面包验证两页布局、搜索、排序、暂停、详情导航和失效选择清理。后端真实自测不等于桌面 UI 全流程验收。

参考：macOS SDK `libproc.h` / `sys/resource.h`（本机接口声明）；`man ps` / `lsof` / `nettop -h`（采集命令）；[sysinfo 进程接口说明](https://docs.rs/sysinfo/latest/sysinfo/struct.Process.html) 对进程信号与权限的注意事项，最终实现直接使用 macOS 原生接口。

## 暂停状态显式结束修复

主智能体桌面验收发现：暂停后真实结束成功，但冻结快照仍保留旧进程。现由成功结束动作记录精确 identity，所有显示快照（包括 paused frozen）都在呈现前剔除已确认退出的进程及关联端口；详情依据相同 identity 查找，因此立即回到空状态。此动作不恢复定时采样，不修改用户的暂停开关。按 identity 过滤，之后复用相同 PID 的其他进程不会被误隐藏。

验证：`node scripts/verify-system-snapshot.mjs` 通过，覆盖暂停快照行 / 端口 / 选中详情清除、原冻结快照不变、PID 复用保留、空快照与未结束快照引用保持。端口详情“复制命令”同步改为项目原生 `writeClipboard` 服务，继续保留失败反馈。

## CPU 时间单位修复（2026-10-16）

新增真实单核忙循环回归测试 `cargo test --manifest-path src-tauri/Cargo.toml --lib system::tests::single_busy_core_has_plausible_process_cpu_percent -- --nocapture`。修复前实际显示 2.00%，断言失败；检查本机 `mach_timebase_info` 为 numer=125、denom=3，原来把 Mach absolute ticks 当纳秒，导致低估约 41.67 倍。现在对 CPU 计数差值按系统 timebase 换成纳秒再计算，timebase 读取失败时返回不可用，不假定 1:1。磁盘字节计数和采样间隔不变。

修复后同一回归测试测得 92.16%，系统模块 8 项测试通过。纯计算测试覆盖 Apple Silicon 125/3、Intel 1/1、多核 200% 和无效 timebase。本次单位修复时进程表按单核满载 100% 显示，悬浮球按整机 0–100% 显示（后续统一口径见下节）；进程表「我的进程」筛选也不会涵盖系统进程，二者不能直接比较或直接求和。表头与悬浮球指标名称已明确区分口径。

原生结构体字段已与本机 SDK / [Apple XNU rusage_info_v2 定义](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/resource.h)核对，字段布局无偏移。此前测试只断言 CPU > 0，未识别几十倍的比例错误，现保留量级回归测试。


## 进程 CPU 统一为整机比例（2026-10-16）

保留 Mach timebase 换算，将进程 CPU 再除以 macOS 在线逻辑核心数；核心数读取失败时显示不可用。进程列表和详情统一消费后端归一化结果，悬浮球保持整机 CPU 采集方式。10 核机器一个核心满载约 10%，两个核心约 20%，全部核心满载约 100%。

`cargo test --manifest-path src-tauri/Cargo.toml --lib system::tests -- --nocapture`：8 项通过。纯计算覆盖不同 timebase、1/10 核、整机满载与无效核心数；真实忙循环在本机 10 核下测得整机占比 7.11%（并行测试期间实际负载有波动）。用户筛选、权限及独立采样时刻仍会导致进程列表合计与悬浮球数值存在差异。
